# Direct USB printing for the iDPRT SP310

The SP310 is a 3-inch (76 mm) thermal label printer, 203 dpi, meant to
replace the intake stations' DYMO LabelWriter 450 Turbo for the small package
labels. It speaks plain TSPL, so it needs no driver: ibp-printing talks to it
over USB like the PM2411BT ([pm2411bt.md](pm2411bt.md)), through its own
job builder and session (`ibp_printing/direct/plain_tspl.py`).

## Verified on real hardware (2026-11-26, Arch laptop, usblp)

- USB `20d1:7008` (iDPRT), iProduct "SP310", serial present. One interface:
  printer class 7/1 proto 2 (bidirectional), bulk OUT 0x02, bulk IN 0x82.
- 1284 ID: `MANUFACTURER:iDPRT;COMMAND SET:ESC/POS;MODEL:SP310;COMMENT:Impact
  Printer;ACTIVE COMMAND:ESC/POS;`. It says ESC/POS but takes TSPL (the
  vendor's CUPS driver, `rastertolabeltspl` with `sp310.tspl.ppd` 1.4.8,
  sends TSPL). Identified by `MODEL:SP310`.
- `/dev/usb/lpN` is `root:lp 0660`; the udev rule's `20d1` line gives the
  desktop user an ACL.
- **Status:** TSPL's real-time query `ESC ! ?` (`1B 21 3F`, no CR LF) is
  answered at once with one byte, also mid-print: `0x00` ready, `0x20`
  printing, `0x40` cover open. The other bits used (TSPL's documented ones):
  `0x01` head open, `0x02` paper jam, `0x04` out of paper, `0x10` paused,
  `0x80` other error. `~!T`, `~!I`, `~!@` and `ESC ! S` got no reply.
- **A label:** status `0x00` before, `0x20` from ~10 ms after the job is
  written until it has printed (~2.2 s for a 36 x 89 mm label), then `0x00`.
  So a print can be confirmed: printing seen, then ready. Right after a job
  the printer may refuse the next write for a moment (`EAGAIN`); the session
  treats that as an unanswered query and asks again.
- **The job** (as the vendor filter, no compression, no `DENSITY`/`SPEED`:
  the printer's defaults):

  ```text
  \r\nSIZE 36 mm,89 mm\r\nGAP 3 mm,0 mm\r\nDIRECTION 0,0\r\nREFERENCE 0,0\r\n
  CLS\r\nBITMAP 0,0,36,712,0,<36 x 712 bytes>\r\nPRINT 1,1\r\n
  ```

  `BITMAP` mode 0, 8 dots per byte MSB first, a 0 bit prints black (the same
  packing as the PM2411BT's raster). 288 x 712 dots for 36 x 89 mm.
- **Placement:** on 36 x 89 mm labels the full raster overran the label by
  under 1 mm on two sides (a 0.5 mm border lost on one long side and partly
  on one short side; lines 1 mm in were all visible). The model keeps a 1 mm
  white margin, so the image is fitted to 34 x 87 mm, centered.
- **Package label:** the backend's 1004x378 request label is rotated to
  portrait and scaled to about 262 x 696 dots; its Code 128 still decodes
  (zbar) after rasterizing.

## Media

TSPL printers cannot report the label size, so it is part of the model
(`ibp_printing.printers.SP310.media`): 36 x 89 mm (1.4 x 3.5 in, the DYMO
30321 size), 3 mm gap, 1 mm margin. A different roll needs a different
`Media` there.

## Outcomes

| Printer says | Result |
|---|---|
| no reply to two status queries before the job | `DirectPrintError` `no_status_reply`, nothing sent |
| cover/head open, out of labels, jam, paused, other error | `DirectPrintError` (`cover_open`, `paper_out`, `paper_jam`, `paused`, `printer_error`), nothing sent, volunteer message |
| still printing a previous label after 10 s | `DirectPrintError` `printer_busy`, nothing sent |
| printing (`0x20`), then ready | `COMPLETED` |
| still printing after `done_s` (30 s) | `TIMEOUT` |
| an error bit after the job | `ERROR` (part of a label may have come out) |
| never printing within `doing_s` (10 s), a stalled write, the printer lost | `UNCERTAIN` |

As for the PM2411BT, the job is never resent.

## On an intake station

ibp-print-server runs as a system service, so the udev rule's ACL (for the
active desktop session) does not reach it: the service user needs the node's
group (`SupplementaryGroups=lp`, in the unit in `packaging/linux/`). If a
CUPS queue for the SP310 is still installed, it must not be printing at the
same time: CUPS's usb backend takes the device from usblp while it prints.
